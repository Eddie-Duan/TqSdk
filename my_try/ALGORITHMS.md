# 量化研究：算法地图与工作流程

> 本文档汇总了本项目从"能不能用 TqSdk 做交易"到"完整做完一个策略研究"的全过程，
> 包含：**策略骨架 → 算法地图 → 研究流程 → 实战案例 → 坑清单 → 数据边界**。
>
> 读者背景假设：会用 Python、懂基础经济学（供需、均衡、套利），不要求金融工程基础。

---

## 0. 一句话结论（先看这个）

我们用一个公开的双均线趋势策略，在螺纹钢 4.75 年小时数据上做了完整检验，结论是：

> **价格里确实存在统计上可测量的微弱趋势结构（VR(40)=1.06），但它①不显著、②无法实时利用、③扣除真实成本后收益接近于零。这与有效市场假说一致 —— 公开、可复制、无信息优势的策略不应产生持续超额收益。**

**这个"否证"过程本身，比任何一个收益率数字都更有价值。**

---

## 1. 策略的七个层（骨架）

一个交易策略不是"选个预测算法"，而是七层的串联。缺任何一层都不成立：

```
① 数据层   取什么行情          → api.get_kline_serial / get_quote
② 特征层   从行情算出指标      → 均线、价差、持仓量变化……
③ 信号层   何时进、何时出      → ★ 必须同时定义"进"和"出"
④ 仓位层   下几手              → ★ 最容易被跳过，也最要命
⑤ 风控层   亏到什么程度必须走  → 止损、敞口上限
⑥ 执行层   怎么把单子发出去    → 小单直接下单，大单才需要算法
⑦ 评估层   跑完怎么判断好坏    → 收益、回撤、夏普、成本占比、稳健性
```

| 层 | 小项目要不要 |
|---|---|
| 数据 / 特征 / 信号 | ✅ 必需 |
| **仓位 / 风控** | ✅ 必需（大多数人只写①②③就开跑） |
| 评估 | ✅ 必需（这才是研究的产出） |
| 执行算法 | ❌ 单笔几手不需要（TWAP/冰山是给几百手用的） |
| 组合优化 | ❌ 单品种用不上 |

参考实现：`04_strategy.py`（代码里用 `---------- ① ② ③` 标出了这七层）

## 2. 算法地图：按"信息源"分三层

**决定成败的不是算法名字，而是信号从哪来。** 所有均线、RSI、布林带本质都是"从价格推测价格"，信息量没有增加。

### 2.1 第 1 层：无锚（纯价格派生）

| 类别 | 代表算法 | TqSdk 现成文件 |
|---|---|---|
| 均线类 | EMA、HMA、KAMA、双/三均线 | `doublema.py`、`hull.py` |
| 通道突破 | 唐奇安通道、肯特纳、布林带 | `turtle.py`、`Keltner_Channel.py`、`aberration.py` |
| 动量/振荡 | RSI、CCI、CMO、Aroon、TRIX | `RSI.py`、`CCI.py`、`CMO.py`、`Aroon.py`、`TRIX.py` |
| 趋势强度 | ADX、Vortex、Qstick | `vortex-indicator.py`、`Qstick.py` |
| 日内突破 | Dual Thrust、R-Breaker、枢轴点 | `dualthrust.py`、`rbreaker.py`、`pivot_point.py` |
| 均值回归 | Z-score、距离偏离 | `z_score.py`、`distance_based.py` |
| 网格/加仓 | 网格、阶梯加仓 | `gridtrading.py`、`escalator.py` |
| 形态 | 分形、四价模型 | `fractal-trend.py`、`fairy_four_price.py` |
| 机器学习 | 随机森林等 | `random_forest.py` |

> ⚠️ **本层天花板很低**（已被本项目实证）。换算法不改变结论。

### 2.2 第 2 层：数据锚（同品种的另一维度）— 性价比最高

| 信号 | 逻辑 | 数据从哪来 |
|---|---|---|
| **持仓量 OI** | 价涨+OI增=新资金入场（可信）；价涨+OI减=空头回补（可疑） | ✅ K线里已有 `open_oi`/`close_oi` |
| **量价关系** | 放量突破 vs 缩量突破 | ✅ `volume` |
| **波动率状态** | 波动率聚集；低波动后常有突破 | ✅ 可算 |
| **基差/期限结构** | 近月−远月，反映库存与便利收益 | ✅ 多合约价格 |
| **日内时段** | 开盘区间突破、夜盘 vs 日盘 | ✅ K线自带时间 |

参考：`volume_price.py`、`11_basis_test.py`

### 2.3 第 3 层：理论锚（经济关系）— 最值得投入

| 策略 | 理论依据 | 数据 |
|---|---|---|
| **期限结构 / 跨期** | 持有成本模型 $F = S·e^{(r+u-y)T}$ + 便利收益 | 多合约价格 |
| **季节性** | 螺纹"金三银四"、农产品播种收割周期 | 多年历史 |
| **展期收益** | Backwardation 时做多可赚展期 | 多合约价格 |
| **库存 / 仓单** | 供需最直接证据 | 交易所公布（需手工） |

### 2.4 多商品策略

| 类别 | 逻辑 | TqSdk 现成文件 |
|---|---|---|
| **产业链利润** ⭐ | 加工利润偏离 → 刺激/抑制生产 → 回归 | `rb-i-jt-spread.py`（螺纹-铁矿-焦炭）、`crush_spread.py`/`smash_spread.py`（大豆压榨）、`crack_spread_arbitrage.py`（原油裂解）、`mto_spread.py`（甲醇制烯烃）、`pta_spread.py`（PTA产业链） |
| **替代/同族价差** | 替代品比价有稳定区间 | `cu-al-spread.py`、`oi-y-p-spreads.py`、`jm-j-spread.py` |
| **配对/协整** | 长期同步的两品种，偏离回归 | `kalman_filter_pairs_trading.py`、`z_score.py` |
| **跨期价差** | 同品种近月 vs 远月 | `stock-future-cross-period-spread.py` |
| **执行算法** | 不是信号，是"怎么下单" | `vwap.py`、`pov.py`、`iceberg_algorithm.py`、`handicap_algorithm.py` |

**⭐ 首推 `rb-i-jt-spread.py`**：它就是本项目的螺纹钢产业链 ——

```
一吨螺纹 ≈ 1.6 吨铁矿 + 0.5 吨焦炭 + 其他
钢厂利润 = 螺纹 − 1.6×铁矿 − 0.5×焦炭 − 其他
利润过高 → 增产 → 螺纹跌/原料涨 → 利润回落
利润过低 → 减产 → 反向
```

**有实体经济的锚，不像均线靠"历史上看起来还行"。**

### 2.5 TqSdk 自带的 40+ 策略在哪

`tqsdk/demo/example/` —— 全部是可直接运行的完整策略，按上面的表对号入座即可。

## 3. 研究流程（七步法）

做完本项目总结出的标准流程。**顺序不能跳，跳了就白做。**

| 步 | 做什么 | 不做会怎样 |
|---|---|---|
| 1 | **写出假设** | 没有假设就是数据挖掘 |
| 2 | **用最笨的参数做基线** | 没有基线，无法判断复杂方法是否真的有提升 |
| 3 | **参数热力图**（高原 or 孤岛） | 会把"碰巧最好的参数"当成答案 |
| 4 | **样本外 / 更长历史验证** | 本项目 5 个月 → 4.75 年，结论直接反转 |
| 5 | **独立方法交叉验证** | 单一方法的结论可能只是拟合 |
| 6 | **成本敏感性**（平衡手续费） | 会高估收益；TqSim 默认费率比真实低一个量级 |
| 7 | **机制解释** | 不知道"为什么"，就无法判断它何时会失效 |

### 补充：策略失效的两种原因必须分开

| 现象 | 判断方法 | 处方 |
|---|---|---|
| **成本问题** | 毛利 > 0，但平衡手续费很低 | 降频、降成本 |
| **信号问题** | 毛利 < 0（零成本也亏） | 换信息源，不是换参数 |

本项目实证：`5/20` 是成本问题（平衡手续费 3.8 元/手），`20/60`/`30/90` 是信号问题（平衡手续费为负）。

## 4. 实战案例：螺纹钢双均线（六步证据链）

```
1. 5 个月样本   → 慢参数最好（20/60 夏普 2.03）      ← 诱人但脆弱
2. 4.75 年验证  → 20/60 亏 6.8%                      ← 结论被推翻
3. 参数热力图   → 有"高原"（fast 8~12 / slow 25~40）  ← 不是纯噪声
4. 方差比检验   → VR 在 q≈5~50 > 1，与高原吻合        ← 独立方法互证
5. 逐年 VR      → 2025 转均值回归，正是唯一亏损年      ← 解释"何时失效"
6. 平衡手续费   → 分出"成本问题"和"信号问题"          ← 解释"为何失效"
7. regime 过滤  → 收益 18.8% → 7.5%，夏普 0.61 → 0.42 ← 尝试利用，失败
```

**最终落点：这个趋势结构是「事后可见，事前不可用」的。**

对应的脚本：

| 脚本 | 做什么 |
|---|---|
| `04_strategy.py` | 完整策略（七层骨架），TqApi 回测 |
| `07_hist_range.py` | 数据体检：各类合约能回溯多长 |
| `08_robust_test.py` | 逐年收益矩阵 + 参数热力图 + 成本敏感性 |
| `09_variance_ratio.py` | 方差比检验：趋势存在于哪个尺度 |
| `10_regime_filter.py` | 滚动 VR 可预测性 + regime 过滤实战 |
| `11_basis_test.py` | 期限结构 / 基差分析（样本 0.67 年，单一 Contango 期） |
| `12_basis_long.py` | **期限结构长样本检验**：按换月表拼接「主力−次主力」对，样本扩到 4 年 |
| `13_basis_multi.py` | **期限结构换腿距 + 跨品种**：腿距 1/2 × 6 个品种，做外部效度检验 |
| `14_cross_section.py` | **横截面检验**：从「1 品种 × 4.75 年」转为「N 品种 × 每月调仓」，检验 carry / 展期收益因子（已离开单品种时间序列的范畴） |

## 5. 坑清单

### 5.1 技术坑（改代码时会踩）

| 坑 | 现象 | 正解 |
|---|---|---|
| **用未收盘的K线算信号** | 交叉信号被吞掉、信号与成交对不上 | 判断信号时排除最后一根：`close[:-1]` |
| **单合约生命周期** | 一个合约只有约 12 个月历史 | 长历史研究用 `KQ.i@`（指数）或分段拼接 |
| **主连换月跳空** | 假交叉污染信号 | 用指数合约 `KQ.i@`（加权平均，连续） |
| **主连不能直接交易** | `TargetPosTask("KQ.m@...")` 报错 | 用 `quote.underlying_symbol` 取真实合约 |
| **主连K线在回测里历史不足** | 回测前几个月无数据、策略空转 | 信号与交易都用真实合约 |
| **K线时间戳是纳秒** | CSV 里显示 `1.77e+18` | `datetime.fromtimestamp(ns/1e9, tz=+8h)` |
| **TqSdk 不提供保证金率** | 无法算杠杆 | 用假设值，或 `TqSim.set_margin()` 手动设 |
| **`get_kline_serial` 8000 根上限** | 小时线约 4.75 年、日线约 10 年 | 够用；更长需分段 |
| **`DataDownloader` 需付费账户** | 免费账户报错 | 用 `get_kline_serial` |
| **Windows 中文编码** | CSV 在 Excel 里乱码 | 写文件用 `encoding="utf-8-sig"` |

### 5.2 方法论坑（比技术坑致命）

| 坑 | 表现 | 正解 |
|---|---|---|
| **样本太小** | 5 个月 10 次交易就下结论 | 至少几十次交易 + 多个完整年度 |
| **参数过拟合** | 挑出历史最优参数 | 找"参数高原"而不是"最高点" |
| **统计显著 ≠ 实际有用** | r=−0.026, p=0.024 就以为发现了规律 | 同时看 $\|r\|$、$r^2$、分组是否单调 |
| **前视偏差** | 用未来数据做判断 | 判断只用过去数据（滚动窗口） |
| **滞后 ≠ 平滑** | 滚动指标是"回顾"而非"状态" | 用未来收益做严格的预测力检验 |
| **只看收益率** | 忽略回撤、成本、稳健性 | 永远把收益和回撤一起看 |
| **忽略成本** | TqSim 默认 ≈0.31 元/手，真实 1~3 元/手 | 做成本敏感性，算"平衡手续费" |
| **选择性报告** | 只贴赚钱的回测 | 把失败的实验也写进报告 |
| **数据窥探** | 看到结果后才想到的策略 | 先有假设，再检验 |
| **VR<1 不等于可预测** | 价差 VR=0.53 就以为可以择时 | VR 说"有界"，corr 才说"可预测"。买卖价差跳动(bid-ask bounce)本身就会造成 VR<1 |
| **恒等变换冒充改进** | 把价差除以"合约月差"当成年化 carry | 段内月差是常数 → 只是乘了个正常数 → VR/分位/corr 三个统计量全部免疫。**改函数形式前先问"信息变了吗"** |
| **输出里的天文数字** | 打印出 `584107745473` 元/吨 | 不可能的数 = bug 的路标。本项目两次都靠这条定位到错误 |
| **为拼接数据裁剪窗口** | 14 段跨 4.8 年却报 9.2 年 | `get_kline_serial` 返回整个合约生命周期，拼接时必须裁到段窗口内 |

## 6. 数据边界（TqSdk 能给你什么）

| 标的 | 1 小时线可回溯 | 备注 |
|---|---|---|
| `KQ.i@SHFE.rb` 指数 | **≈4.75 年**（8000 根上限） | 连续无跳空，但不能交易 |
| `KQ.m@SHFE.rb` 主连 | ≈4.75 年（日线约 10 年） | 有换月跳空，不能交易 |
| 真实合约（如 `SHFE.rb2610`） | **≈11 个月** | 可交易，受合约生命周期限制 |

| 能力 | 免费版 |
|---|---|
| 回测次数 | 不限 |
| K线每序列上限 | 8000 根 |
| `DataDownloader` 历史下载 | ❌ 需付费 |
| 保证金率 | ❌ 不对外提供 |
| 实盘交易 | ⚠️ 需专业版（部分期货公司免费） |

## 7. 优先级建议

| 优先级 | 方向 | 理由 |
|---|---|---|
| 🥇 | **产业链利润价差**（`rb-i-jt-spread.py`） | 理论锚强 + 数据可得 + 就是本项目的螺纹 |
| 🥈 | **期限结构 / 基差**（`11_basis_test.py`） | 理论锚强（持有成本 + 便利收益） |
| 🥉 | **持仓量 OI 类信号** | 零成本（数据已有）+ 信息维度不同 |
| 4 | 配对/协整 | 有统计锚，但商品横截面小 |
| ❌ | 换更多技术指标 | 天花板已实证很低 |
| ❌ | 机器学习 | 只有价格数据 + 官方基准显示树模型都难打赢简单规则 |
| ❌ | 社交情绪（雪球等） | **历史数据不可得 → 无法回测** |
